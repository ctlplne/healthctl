# Independent clinical and handoff evaluation

This local instrument prepares blinded reading assignments, records time, captures free responses, and scores independent reviewers’ judgments. It has not been run with patients or clinicians. The two bundled handouts are authored **instrument-practice** examples. For a comparison of releases, supply matched, unmodified synthetic handoffs exported from the actual v1 installation and the combined release for each case. Pilot participants should receive only their masked packets. Keep the facilitator directory private.

To rehearse using actual app layouts, run the [local release drill](../../docs/combined-verification.md#reproduce-verification) with `--study-pair`. It prints the same fictional encounter from the retained v1 image and the upgraded app, and saves the two PDFs and a practice manifest in `build/study-pair/`. Run `python3 evaluation/study/study.py prepare build/study-pair/case.json /tmp/clinical-printed-practice` with a fresh output directory to generate masked PDF packets.

1. A clinical lead should approve the intended users, holdout sampling, expected urgency, expected abstention, outcomes, and thresholds **before** looking at model results. Keep the holdout independent from the engineering fixtures. Include each complaint pathway, ambiguous and out-of-scope presentations, and groups relevant to the intended audience. Preserve exact source passages and review dates with the reports. Assemble at least 30 independent fictional cases as an initial feasibility proposal; this sample size alone cannot establish safe performance.
2. Copy the practice manifest format, supply one pair of synthetic handoff files per case, set `practiceOnly` to false, and provide a scoring key for active concern, timeline, warning, and missing information. Use pseudonyms for readers and graders. Allocate the same number of readers per arm. Readers see one format per case. Order is shuffled and adjacent readers receive opposite formats. The reader should not see the assignment key, other readers’ answers or source filenames. Different visible layouts can limit blinding.
3. Run `python3 evaluation/study/study.py prepare evaluation/study/practice/case.json /tmp/clinical-study-practice`. For a real study choose a new private directory. Each pseudonym's `order.json` lists its masked tickets in presentation order.
4. For each ticket, use `python3 evaluation/study/study.py collect DIRECTORY TICKET`. Start timing immediately before the reader opens the assigned handoff. Clinicians recover the active concern, timeline, urgent notice and missing information, and note what they would repeat. Patients explain the warning, clinical review status and meaning of the estimate in their own words. Press Ctrl-C during a session to record abandonment.
5. Two independent qualified assessors can use `python3 evaluation/study/study.py adjudicate DIRECTORY TICKET REVIEWER_CODE`. Review the exact supporting passages and report terms, record the reason, and remain masked to the assigned arm and other assessors’ responses. Qualification and independence require organizer verification.
6. `python3 evaluation/study/study.py score DIRECTORY` prints results by arm, with per-ticket complaint, group, reviewer disagreement, numerator/denominator coverage, ungraded and abandoned sessions. Discordant judgments remain visible for a separately documented, masked resolution. Where two independent reviewers agree, it counts urgent misses, excessive escalation, abstention, misleading explanations, unsupported citations, essential fact recovery, patient understanding and clinician-acceptable briefs. Report subgroup denominators and uncertainty alongside estimates. Repeated readers and repeated cases are correlated. The reported Wilson intervals are descriptive; a prospective analysis should account for clustering.

The proposed software regression threshold is zero invented findings, current stale assessments, or lost warnings across the required cases. The human protocol proposes zero materially misleading explanations, unsupported citations and missed urgent cases, at least 90% essential-fact recovery, appropriate abstention and warning/status comprehension, and at most 15% excessive escalation. The candidate's median clinician reading time should be at most the baseline's. These are engineering proposals requiring clinical and statistical agreement. A small study with zero observed misses cannot prove a zero miss rate. Pricing per clinician-acceptable brief needs actual metered costs and an independently adjudicated denominator.

An optional `costs` object on each manifest case can contain `baseline` and `candidate` objects, each with numeric `modelUSD`, `infrastructureUSD`, and `contentMaintenanceUSD`. Include failed model attempts and document the allocation period and basis for shared costs before analyzing results. Missing costs remain unknown. The instrument divides total cost across all cases by the count of independently accepted unique briefs only when every case in that arm has complete costs and an agreed acceptability result. The practice manifest intentionally leaves costs unknown.

Exercise preparation, masking, timing, independent grading, disagreements, and missing-denominator handling locally with `python3 -m unittest discover -s evaluation/study -v`. This is a scripted instrument rehearsal.

## Interview elicitation pilot

Use `python3 evaluation/study/interview.py prepare /tmp/healthctl-interview-pilot` to prepare a counterbalanced block of eight actors with two fictional experiences each. Each actor receives one variant of each case. The four arms cover healthctl with either answer style selected at intake, an outpatient practice’s usual intake, and ordinary chat using the identical model and reasoning setting. The supplied dizziness and bowel-change cases are for rehearsal. Supply independently designed cases with `--cases` for evaluation. Give actors only their assignment. Ask them to volunteer the opening and then answer faithfully when asked.

Run `python3 evaluation/study/interview.py start FOLDER TICKET` when the participant begins. Use `python3 evaluation/study/interview.py finish FOLDER TICKET --brief MASKED.txt` when they finish. Remove arm identifiers and layout clues from the fictional export and include the transcript for identifying repeated questions. Include `--cost` when measured. Give independent clinicians only the grading packet and keep the arm allocation with the facilitator. Run `python3 evaluation/study/interview.py grade FOLDER TICKET` to record their judgment. Run `python3 evaluation/study/interview.py score FOLDER` to report every assigned case, missing facts, repeat questions, completion time, cost per usable brief, and each reported fabrication, stale estimate, or lost warning. Use a second independent reader and the adjudication procedure above for disputed clinical findings. These practice checks establish software behavior only.

For the desktop usability pilot, give five first-time Docker users an unconfigured Mac and the installer. Time from opening the installer through saving the first fictional interview. Record the runtime installation time separately, which steps needed help, any abandonments, and whether they finished independently within five minutes.
