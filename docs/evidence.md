# Local evidence library

The installation ships eight short educational passages from seven agency pages. The scope covers the common cold, nasal allergies, migraine, abdominal bloating, balance disorders, urinary tract infection symptoms, and laboratory reference intervals. All entries include a publisher, dated source, original section, exact quotation, source link, publisher reuse policy, applicability limits, and verification date. The immutable source manifest is [starter.json](../internal/evidence/starter.json).

## Retrieval and citations

The backend builds an index from the active version of each collection and caches it by immutable content hashes. Passage browsing ranks matches in titles, sections, publishers and quoted text. A phrase that appears in the body can retrieve the passage even when it is absent from topic aliases. The separate question mode accepts curated topic aliases, definitions, and specific condition-and-feature questions supported by a quoted passage. The server displays the exact passage and the limits defined by its source record. It abstains for unsupported questions such as an individual diagnosis, treatment decision, or unknown topic. Search uses POST with an authenticated session and CSRF token. It performs no network request and keeps no search transcript. Opening a publisher link is the user's separate browser action.

The differential stores a passage snapshot, its item index and corpus version, or an explicit unavailable result. A topic-only match is labeled related reading. A supported feature link requires a named condition, a curated concept whose quotation occurs in the source, and an active, confirmed, self-reported positive finding cited by the estimate. The link carries the exact source words, immutable passage reference and matched fact IDs. The passage must also declare general-education applicability and an age interval that includes the patient. An ambiguous population, denied symptom, family history, past-only finding, or report measurement cannot create one of these symptom links. It cannot establish that this person has that condition. During later reads the backend adds the cited version's current lifecycle status. A withdrawn version stays legible on prior results. New searches use active versions only. A failed library lookup leaves the estimate available with a message explaining the missing evidence.

Conflicts are declared by a pack author with full immutable passage references. When either side of a declared relationship matches, the search returns both active passages and identifies the declared disagreement. It also signals an unavailable counter-source. The system does not infer consensus from an empty conflict list. The bundled educational definitions contain no declared disagreements.

## Installing local content

The authenticated owner can import a small JSON collection from evidence settings. The pack uses the format in [starter.json](../internal/evidence/starter.json). Give an operator collection its own ID, version and title. Each entry needs a stable ID, source page and section, a quotation of up to 1,000 bytes, one or more focused topic aliases, publisher, publication/update date, verification date, population, limitations, rights text and rights URL. Explicitly confirm that your installation can store, display, and include excerpts in patient-directed reports under the relevant terms. Operators must verify rights and clinical applicability for their material.

Use lower-case letters, numbers, dots and hyphens for collection, version and passage IDs. Set `applicability.scope` to `manual_review` for restricted or uncertain populations. For broadly applicable educational sources, an explicitly declared `general_education` scope and supported `minAge` and `maxAge` enable age matching. Optional `conditions` and `features` restrict links to named conditions and an exact supporting quotation with its verified concept aliases. Operators must verify the meaning, target population, and limits for each linked feature. For an author's declared conflict, add `collection/version/passage` to `conflictsWith`. Set `reviewStatus` to `unreviewed_for_application` unless a specific review is documented. The alternative `operator_attested` requires a `reviewRecord` explaining who reviewed what and when. Operator-supplied review information has no independent verification by the software. No version can mark a patient's AI estimate as reviewed.

The owner can install a newer version, withdraw a version with a reason, or reactivate a previously stored version to roll back. Installing a new version atomically retires its predecessor. A previously installed version cannot be overwritten. The operation records its version and reason in the local database's lifecycle history. Rollback reuses the exact stored content. The database backup covers the library, its lifecycle history and operator-attested records. Limits are 48 KiB per request, up to 100 entries per pack and 128 collection versions per installation.
